===========================================================================
lenv-cli — manual test scenarios
===========================================================================

Scope:
  Tests for planned DevSpace-backed sync flow on minikube.
  Goal: local IDE save -> file appears inside running pod, dev server reloads.

Engine: DevSpace (thin orchestrator). lenv generates devspace.yaml from
        services[] in lenv.config.yaml, then shells out to `devspace dev`.

Each scenario:
  - Setup     prerequisites + commands to run
  - Expected  observable outcome
  - Pass      criteria for green

===========================================================================
A. PRECONDITIONS (run once before all tests)
===========================================================================

  A1. minikube installed, running
        $ minikube start --driver=docker
        $ kubectl config current-context        # must print: minikube

  A2. lenv-cli installed
        $ npm link  (from repo root)
        $ which lenv                            # must print: .../bin/lenv

  A3. devspace installed
        $ devspace --version                    # must print version
        # if missing: brew install devspace

  A4. test workspace
        $ mkdir -p /tmp/lenv-it && cd /tmp/lenv-it
        $ git init && echo "console.log('hello')" > app.js


===========================================================================
B. doctor + rise (already implemented — regression)
===========================================================================

  B1. doctor with no config
        $ cd "$(mktemp -d)"
        $ lenv doctor
      Expected: "No lenv config file found", exit 1

  B2. doctor with all tools present
        config:
          tools:
            - name: git
            - name: kubectl
            - name: minikube
        $ lenv doctor
      Expected: 3 OK lines, "All required tools present", exit 0

  B3. doctor with required missing
        config:
          tools:
            - name: thistooldoesnotexist
        $ lenv doctor
      Expected: MISSING line, exit 1

  B4. doctor with optional missing
        config:
          tools:
            - name: thistooldoesnotexist
              optional: true
        $ lenv doctor
      Expected: SKIP line, exit 0

  B5. rise installs missing tool
        config:
          tools:
            - name: temptool
              install: echo installed-temptool > /tmp/lenv-mark
        $ lenv rise
      Expected: "installing temptool", "+ temptool installed", exit 0
                /tmp/lenv-mark exists with content

  B6. rise applies kube context
        config:
          kube:
            name: minikube
            namespace: lenv-test
        $ kubectl create namespace lenv-test || true
        $ lenv rise
        $ kubectl config view --minify -o jsonpath='{..namespace}'
      Expected: prints "lenv-test"


===========================================================================
C. up — bring service up with sync (NEW, not yet built)
===========================================================================

  C1. up generates devspace.yaml
        config:
          services:
            api:
              image: node:20-alpine
              repo: ./api
              target: /app
              port: 3000
              command: node /app/server.js
              install: echo "no install"
        $ mkdir api && echo 'require("http").createServer((_,r)=>r.end("v1")).listen(3000)' > api/server.js
        $ lenv up --dry-run
      Expected:
        - prints generated devspace.yaml to stdout
        - YAML contains: dev.api.sync, dev.api.command, dev.api.ports
        - exit 0
        - does NOT actually run devspace

  C2. up runs devspace dev
        $ lenv up
      Expected:
        - "Generating devspace.yaml"
        - "Starting devspace dev"
        - pod `api-*` in current namespace, status Running within 60s
        - port-forward established: localhost:3000 -> pod:3000
        - lenv stays in foreground (devspace attached)

  C3. up validates pod responds
        (with C2 running)
        $ curl -s localhost:3000
      Expected: "v1"

  C4. up errors when no services[]
        config: (no services block)
        $ lenv up
      Expected: "No services defined in lenv.config.yaml", exit 1

  C5. up errors when not on expected context
        config:
          kube: { name: minikube }
          services: { api: {...} }
        $ kubectl config use-context not-minikube
        $ lenv up
      Expected: warns "current kube context != minikube", asks confirm, exit 0 or 2 based on answer


===========================================================================
D. sync — file sync round-trip (THE CORE GOAL)
===========================================================================

  D1. local save reaches pod
        (C2 running)
        $ echo 'require("http").createServer((_,r)=>r.end("v2")).listen(3000)' > api/server.js
        wait ~3s
        $ kubectl exec deploy/api -- cat /app/server.js
      Expected: file content matches local (contains "v2")

  D2. dev server reloads
        (with nodemon or similar in `command`)
        modify api/server.js -> "v3"
        $ curl -s localhost:3000
      Expected: "v3" within 5s of save (no restart, no rebuild)

  D3. install rerun on package.json change
        config:
          services:
            api:
              install: yarn install
        $ echo '{"name":"a","dependencies":{"lodash":"^4"}}' > api/package.json
        wait
        $ kubectl exec deploy/api -- ls /app/node_modules | grep lodash
      Expected: lodash directory present (install ran inside pod)

  D4. sync excludes .git and node_modules
        $ echo "secret" > api/.git/HEAD
        wait 3s
        $ kubectl exec deploy/api -- ls -la /app/.git 2>&1
      Expected: "No such file or directory"

  D5. delete locally -> delete in pod
        $ rm api/server.js
        wait 3s
        $ kubectl exec deploy/api -- ls /app/server.js 2>&1
      Expected: "No such file or directory"

  D6. large file (~50MB)
        $ dd if=/dev/zero of=api/big.bin bs=1M count=50
        $ ls -la api/big.bin
        wait, then:
        $ kubectl exec deploy/api -- ls -la /app/big.bin
      Expected: same size in pod within 30s

        $ lenv logs api &

      Expected: request log line appears in lenv logs output within 2s

===========================================================================
F. down
===========================================================================

  F1. down tears resources
        $ lenv down
        $ kubectl get deploy api 2>&1
      Expected: "deployments.apps 'api' not found"
                exit 0

  F2. down without prior up
        (fresh namespace)
        $ lenv down
      Expected: "Nothing to tear down", exit 0


===========================================================================
G. config edge cases
===========================================================================

  G1. JS config dynamic
        lenv.config.js:
          module.exports = {
            services: {
              api: { image: process.env.IMG || 'busybox', port: 8080 }
            }
          };
        $ IMG=node:20 lenv up --dry-run
      Expected: generated yaml shows image: node:20

  G2. Multiple services
        config:
          services:
            api:   { port: 3000, target: /app/api, repo: ./api }
            web:   { port: 8080, target: /app/web, repo: ./web }
        $ lenv up
      Expected: both pods Running, both port-forwards live

  G3. Port conflict on host
        $ python3 -m http.server 3000 &
        $ lenv up
      Expected: lenv detects port in use, picks 3001 (or errors with clear msg)
